# NEURO-CORE 666 — SAMBU

## Repository responsibility
Language runtime, parser/AST, semantic analysis, scientific workflows

## Architecture integration
Prioritize parser/AST safety, typed IR, deterministic execution, plugin capability boundaries and reproducible scientific workflows. No kernel-mode claims.

## Nine-cluster contract
- **C1 — KERNEL + DELPHI (74 slots):** Typed low-level interfaces, lifecycle inspection, resource ownership, diagnostics.
- **C2 — LUA + TRICKSTER (74 slots):** Capability-limited scripting, deterministic test doubles, honeypots in isolated labs.
- **C3 — BRAIN + NEUROBIOLOGY (74 slots):** Evidence-based anomaly correlation, feedback, bounded adaptation and health.
- **C4 — SCENARIOS + SCRUPLES (74 slots):** Scenario testing, privacy, licensing, human approval and blast-radius controls.
- **C5 — DO + WHAT (74 slots):** Declared intent, semantic change review, transactional actions and provenance.
- **C6 — GIRL + FUDGE (74 slots):** Adaptive UX, safe tolerance bands, graceful degradation and accessible feedback.
- **C7 — QUANTUM + HUMAN (74 slots):** Post-quantum readiness, hybrid crypto migration and human-controlled release gates.
- **C8 — FREE + DEAD (74 slots):** Open formats, dependency lifecycle, dead-code evidence and safe resource cleanup.
- **C9 — JOY + GYM (74 slots):** Fuzzing, performance budgets, recovery drills and non-toxic engineering feedback.

## Delivery and evidence rules
- The manifest at `neuro-core/manifest.json` reserves exactly 666 traceable innovation IDs (9 × 74).
- The 16 named seed capabilities per cluster are proposals, not completed features. The remaining 58 slots per cluster are deliberately marked BACKLOG because the supplied brief does not specify their individual designs.
- A capability may move to `IMPLEMENTED` only with source code, tests, documented platform scope and reproducible CI evidence. A proposal or document is not implementation evidence.
- Kernel, driver, DMA, PCIe, hypervisor and hardware claims require target-specific review and tests; host CI alone is insufficient.
- Script engines and honeypots run only in bounded, isolated test environments. No real credentials, user files or production traffic are used as decoys.
- Destructive remediation, release signing, production deployment and data deletion require explicit human approval.
- Post-quantum work is migration readiness until an audited implementation and interoperability tests exist.

## Initial implementation boundary
This change adds the machine-readable register, safety contract and CI validator. It does **not** claim that all 666 capabilities are implemented, that a neural model is trained, or that hardware-level protections are active.
