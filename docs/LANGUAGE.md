# SAMBU language guide (0.11 baseline)

> This guide describes the implemented Python-hosted interpreter. Native compilation, static type checking, ownership, language-level async and zero-cost abstractions are future targets, not current guarantees. See [Language Evolution Architecture](LANGUAGE_EVOLUTION.md) for the staged systems-language design and [Autonomy Constitution](AUTONOMY_CONSTITUTION.md) for 50 auditable engineering rules.

## Design goal

SAMBU is a small scientific DSL whose syntax keeps equations visible while its runtime tracks physical dimensions. Its initial domain is statistical mechanics and introductory kinetic theory. The name expands to **Statistical Analysis & Modeling with Boltzmann Utilities**.

This is an interpreter prototype, not a claim that SAMBU solves the full Boltzmann equation or Landau kinetic equation. Those require numerical methods, boundary conditions, collision operators, and validation beyond the current release.

## Program structure

A program is a sequence of statements separated by a newline or `;`.

```sambu
let temperature = 300 * K
let mass = 6.6e-26 * kg
let stats = maxwell(temperature, mass)
print(stats.mean)
```

`let` creates an immutable name. Re-defining a name in the same scope is an error. Built-in units and constants are predeclared (`kg`, `g`, `m`, `s`, `K`, `J`, `eV`, `k_B`, `h`, `c`, and others); top-level bindings cannot redefine those names. Nested blocks and functions have child scopes and may shadow an outer name. A program may contain comments beginning with `#`.

## Articulatory syntax (AS-1)

SAMBU supports two equivalent source surfaces. The established spellings (`let`, `fn`, `if`, `return`, `class`, and so on) remain valid. The articulatory surface uses a 200-word lexicon generated by a fixed sound-to-meaning rule:

`onset + vowel grade + grammatical coda`.

Ten consonant families × five vowel grades × four codas create 200 unique two-syllable words. The first syllable is stressed.

| Part | Choices | Semantic purpose |
|---|---|---|
| Onset | `k t r m s v d n p l` | Structure, flow, value, memory, safeguard, measure, evidence, coordination, transform, language |
| Vowel | `a e i o u` | Initiate, inspect, transform, compose, complete |
| Coda | `-va -ven -vir -vum` | Action, entity, relation, state |

For example, `kava` means a structure-opening action and is the source word for `let`; `kaven` is a structural entity and maps to `class`; `kavir` is a structural relation and maps to `extends`.

### Executable grammar example

```sambu
kava temperature = 300 * K
kava particle_mass = 6.6e-26 * kg
kava profile = vava(temperature, particle_mass)

tava square(value) {
  tavum value * value
}

teva square(5) > 0 {
  lava(profile.rms)
  lava(square(5))
} teven {
  lava(0)
}
```

The example uses `kava` (`let`), `tava` (`fn`), `tavum` (`return`), `teva` (`if`), `teven` (`else`), `vava` (`maxwell`) and `lava` (`print`). The original source spelling is retained on each token as `lexeme`; the normalized token value and parser behavior remain canonical. Source spans still refer to the exact characters typed.

### Wordbook status

| Status | Count | Meaning |
|---|---:|---|
| Grammar | 25 | Executable keyword aliases |
| Built-in | 129 | Executable aliases to existing runtime functions |

Reserved words are not silently interpreted. Query a word from source with `word_info("kava")` (articulatory form `leven("kava")`) or list the lexicon with `wordbook()` (articulatory form `levir()`). The CLI also exposes `sambu lexicon --status reserved`.

The complete word-by-word definitions and sound families are in [Articulatory Syntax](ARTICULATORY_SYNTAX.md). For provenance-led experiments that design token sets and grammar productions, see [Language Craft](LANGUAGE_CRAFT.md). The old syntax remains source-compatible, and articulatory forms can be mixed with canonical keywords during migration.

## Expressions

Supported values are numbers, strings, booleans, `null`, arrays, quantities, and records returned by scientific functions. Expressions support function calls, array indexing, and record-field access.

Operator precedence, highest to lowest:

1. Function calls, indexing, and field access
2. Unary `-`, `+`, `!`
3. `^` / `**` (right associative)
4. `*`, `/`
5. `+`, `-`
6. `<`, `<=`, `>`, `>=`
7. `==`, `!=`
8. `&&` / `and`
9. `||` / `or`

Use explicit multiplication for units: `300 * K`, not `300 K`.

## Physical quantities

All quantities are stored internally in SI base units. Addition, subtraction, and comparison require matching dimensions. Multiplication and division combine dimensions. Integer powers preserve dimensional meaning. Fractional powers of dimensioned quantities remain deliberately rejected.

### Built-in units

| Name | SI value |
|---|---:|
| `kg`, `g` | 1 kg, 0.001 kg |
| `m`, `cm`, `km` | 1 m, 0.01 m, 1000 m |
| `s`, `ms` | 1 s, 0.001 s |
| `K` | 1 kelvin |
| `mol` | 1 mole |
| `J`, `kJ`, `eV` | 1 J, 1000 J, 1.602176634e-19 J |
| `Pa`, `bar` | 1 Pa, 100000 Pa |
| `Hz`, `N`, `L` | hertz, newton, litre |

### Constants

`k_B`, `h`, `hbar`, `c`, `N_A`, `R`, `G`, `pi`, and `e` are predefined. SI exact values are used where defined; constants with measured values use the values documented in source code.

## Scientific standard library

| Function | Signature | Result |
|---|---|---|
| `thermal_energy` | `thermal_energy(T, dof=3)` | Mean equipartition energy, `(dof/2) k_B T` |
| `maxwell` | `maxwell(T, particle_mass)` | Record with `most_probable`, `mean`, `rms`, `component_sigma` (all speeds) |
| `boltzmann` | `boltzmann(E, T)` | Dimensionless factor `exp(-E/(k_B T))` |
| `partition` | `partition(energy_levels, T)` | Discrete sum of Boltzmann factors |
| `entropy` | `entropy(probabilities)` | Shannon/Gibbs entropy in nats; probabilities must sum to 1 |
| `sample_maxwell` | `sample_maxwell(T, particle_mass, count, seed=0)` | Reproducible Maxwell speed samples |
| `mean` | `mean(array)` | Arithmetic mean |
| `variance` | `variance(array)` | Unbiased sample variance |
| `sqrt`, `exp`, `log`, `abs` | scalar helpers | Elementary operations |
| `count` | `count(array)` | Number of array items |
| `print` | `print(value)` | Writes a formatted value to standard output |

`T` must be a positive temperature. Particle mass must be positive. `partition` accepts an array of energies. `entropy` accepts non-negative probabilities summing to one and returns nats (divide by `log(2)` for bits).

## Numerical scope and limitations

- The interpreter uses Python floating-point arithmetic (IEEE-754 double precision).
- Arrays are ordinary interpreted lists, not vectorized tensors.
- The Maxwell distribution helpers assume a classical ideal-gas particle with three translational degrees of freedom.
- `partition` is a finite discrete sum; it does not calculate a continuum density of states.
- `sample_maxwell` draws three independent Gaussian velocity components and returns their speed magnitude. Its default seed is `0` for repeatability.
- Unit conversion is implicit to SI at input; display formatting chooses a small set of common derived units.
- User-defined functions and bounded loops are available. No file I/O, network access, imports, mutable assignment, or arbitrary Python evaluation are exposed to SAMBU programs.

## Error model

Lexical and parse errors include one-based line/column information, a stable code, and an end-exclusive source range. Runtime errors are surfaced by the CLI with the source filename. Dimension mismatch, invalid temperatures, invalid probabilities, unknown names, and duplicate bindings fail explicitly instead of silently coercing values.

### Source locations, typed AST and parser API

The public package exports `SourcePosition`, `SourceSpan`, `Token`, `SambuSyntaxError`, `tokenize`, `parse`, and `parse_ast`.

- `SourcePosition(offset, line, column)` uses a zero-based Python string offset (Unicode code points) and one-based line and column numbers.
- `SourceSpan(start, end)` is end-exclusive. Its `is_empty` property identifies a point range.
- Each lexer `Token` retains the original `kind`, `value`, `line`, and `column` fields and adds a `span` property, `end_line`, `end_column`, `start_offset`, and `end_offset`.
- `SambuSyntaxError` retains `line` and `column`, and adds `code` and `span`. Its human-readable exception string keeps the existing line/column format.
- Current diagnostic codes are `SAMBU-L001` (unexpected character), `SAMBU-L002` (unterminated string literal), and `SAMBU-P001` (parser syntax error).

`parse(source)` continues to return the established tuple-based AST so existing interpreter clients do not break. `parse_ast(source)` returns an immutable `Program` containing typed statement and expression nodes. Every node carries an end-exclusive `SourceSpan`; parenthesized expressions include their parentheses in the expression range. `Program.to_legacy()` converts the typed tree to the exact legacy tuple shape. Token and AST offsets count Python Unicode code points; LSP integrations must convert them to the negotiated protocol position encoding (commonly UTF-16). Semantic diagnostics still require a separate analyzer and are not yet produced by `parse_ast()`.

## Control flow and functions

User-defined functions use lexical scope and return values:

```sambu
fn square(x) { return x * x }
print(square(12))
```

Conditionals use `if` and optional `else`; conditions are evaluated as booleans/truthy values:

```sambu
if (temperature > 300 * K) {
  print("above reference temperature")
} else {
  print("at or below reference temperature")
}
```

Bounded iteration uses `for name in array_or_range { ... }`. The standard `range(stop)`, `range(start, stop)`, and `range(start, stop, step)` functions generate integer arrays. `sum`, `min`, `max`, and `len` are also available. Both `range` and `for` enforce a 100,000-item safety cap. Blocks create child scopes; `let` names are immutable. Local bindings can shadow standard-library names. See [Domain Models](DOMAINS.md) for the application library.


## Experimental concurrency primitives

The current interpreter exposes a deliberately small, bounded actor API. It does not add asynchronous syntax or parallel execution to the source grammar.

| Built-in | Signature | Behavior |
|---|---|---|
| `actor` | `actor(handler, initial_state, mailbox_capacity=256)` | Create a sequential actor; `handler(state, message)` returns the next state |
| `actor_send` | `actor_send(actor, message)` | Add a bounded JSON-shaped value to the FIFO mailbox |
| `actor_drain` | `actor_drain(actor, max_messages=1)` | Process messages sequentially up to a work limit |
| `actor_state` | `actor_state(actor)` | Return a defensive state copy |
| `supervisor` | `supervisor(strategy, max_restarts=3, window_seconds=60)` | Create a restart supervisor |
| `supervise` | `supervise(supervisor, actor_or_supervisor)` | Attach a child to a supervision tree |
| `supervisor_status` | `supervisor_status(supervisor)` | Return bounded status and recent restart events |
| `channel` | `channel(type_name, capacity=64)` | Create a bounded software FIFO channel |
| `channel_send` | `channel_send(channel, value)` | Type-check and enqueue a value |
| `channel_receive` | `channel_receive(channel)` | Dequeue one value without blocking |

Actor handlers accept exactly two parameters. Supported payloads are JSON-shaped values: null, booleans, finite numbers, strings, arrays and string-keyed objects. The runtime enforces payload byte, depth and item limits. Each handler receives a working copy; state is committed only after a successful return and validation. Failed messages are added to a bounded dead-letter history.

Supervision strategies are `one_for_one`, `one_for_all` and `rest_for_one`. Restart budgets are rolling-window limits. Restart resets actor state to the initial snapshot, leaves pending mailbox entries queued and does not retry the failed message automatically. A supervisor that exhausts its budget escalates to its parent.

Typed channels currently support `int`, `integer`, `float`, `number`, `text`, `string`, `bool` and `boolean`. Send is non-blocking and fails on a type mismatch or full queue; receive fails on an empty queue.

### Python-hosted runtime APIs

The package also exports `FiberScheduler`, `yield_now()`, `sleep_ticks(n)`, `ResourceScope`, `ModuleMetadata` and `DualAuthorizationGate`.

- `FiberScheduler` cooperatively resumes Python generators in deterministic FIFO order. Its logical sleeps do not block the host thread.
- `ResourceScope` closes owned resources in reverse registration order and reports cleanup failures.
- `ModuleMetadata` validates descriptive module fields; it does not act as a compiler directive.
- `DualAuthorizationGate` invokes two independent verifier callbacks. A real HSM/TPM must be provided by the host.

These APIs are experimental Python-host features. The scheduler does not create OS threads, allocate native fiber stacks, preempt running code or execute tasks across cores. There is no language-level `yield`, `async`, `await`, static race detector, hardware bus or bundled HSM implementation. See [Cripple Systems Architecture](CRIPPLE_SYSTEMS_ARCHITECTURE.md) for guarantees, limits and the native-runtime roadmap.
